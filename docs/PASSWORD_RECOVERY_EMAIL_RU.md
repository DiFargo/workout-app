# Письмо восстановления пароля Zmena

## Причина

В production Firebase Auth стояли стандартный английский шаблон
`Reset your password for %APP_NAME%`, язык `en` и отсутствие имени отправителя.
В `%APP_NAME%` подставлялось техническое название проекта.

## Единый список приёмки

- [x] В production включён русский язык уведомлений по умолчанию; read-back
  подтвердил `defaultLocale=ru` и русский стандартный шаблон Firebase.
- [ ] Публичное имя Public-facing / OAuth brand name проверено и при
  необходимости изменено на `Zmena`; подстановка в новом письме подтверждена.
- [ ] Тема «Смена пароля Zmena», имя отправителя «Zmena».
- [ ] Русский текст, понятная кнопка и запасная ссылка; нет технического
  названия проекта и сырой длинной ссылки в тексте.
- [x] Сохранён штатный одноразовый механизм Firebase; Auth providers,
  authorizedDomains, action URL, SMTP и DNS не изменяются.
- [x] Локальный просмотр подготовленного письма проверен на мобильной и
  настольной ширине. Это пока не опубликованное оформление.
- [ ] В production точечно обновлены только шаблон Password reset и язык
  уведомлений по умолчанию; read-back совпал с подготовленным файлом.
- [ ] Пользователь проверил новое письмо и смену пароля своего тестового
  аккаунта; письмо не отправлялось агентом без отдельного согласия.

## Границы

Изменяется конфигурация уведомлений Firebase Auth, а не клиентский runtime.
Пакет приложения и версия Hosting 3.0.865 не меняются. Источник шаблона:
[firebase-auth-reset-email.ru.json](../config/firebase-auth-reset-email.ru.json).

Системное `defaultLocale=ru` покрывает запросы как через клиентский SDK,
так и через серверный REST без явного заголовка локали. Изменение касается
языка уведомлений по умолчанию; проверка и смена email продолжают использовать
прежние шаблоны и тот же обработчик Firebase.

Попадание письма в спам не считается исправленным изменением текста. По одному
скриншоту невозможно проверить SPF/DKIM/DMARC и репутацию отправителя. Свой
почтовый домен, DNS и почтовый транспорт требуют отдельного согласования.

## Проверка и применение

23 октября 2026 года выполнено:

- Проверка JSON: разрешены только пять подготовленных полей; одна подстановка
  `%EMAIL%` и две `%LINK%`; нет JavaScript, форм и внешних ресурсов.
- Локальный Chromium, 320×720 и 600×850: горизонтальное переполнение 0 px,
  кнопка 223×52 px; русские заголовок и действие, две одинаковые фиктивные
  ссылки. Переходов по ним и внешних запросов не было, браузер закрыт.
- Скриншоты:
  [мобильный](../output/playwright/password-reset-email-mobile.png),
  [настольный](../output/playwright/password-reset-email-desktop.png).
- Попытка применить подготовленные пять полей отклонена Firebase HTTP 400:
  `EMAIL_TEMPLATE_UPDATE_NOT_ALLOWED`. Повторное чтение подтвердило, что эта
  попытка ничего не изменила.
- Отдельное изменение только `notification.defaultLocale=ru` принято HTTP 200.
  Подтверждено чтением `2026-10-23T04:56:31.281Z` (07:56:31 по Минску).
  Сервис вернул русскую тему `Сброс пароля для приложения "%APP_NAME%"` и
  русский стандартный body. SHA-256 body:
  `c099c0ac2b7aab621f34b1c39f61e602e52399609404f893d6f9c037f466dfb0`.
- Отдельная попытка изменить лишь тему и имя отправителя также отклонена
  HTTP 400 `EMAIL_TEMPLATE_UPDATE_NOT_ALLOWED`. Дальнейшие попытки не делались.
- Повторное чтение подтвердило неизменность action URL, способа отправки и
  authorizedDomains. Письма не отправлялись, пароли и аккаунты не менялись.

**Состояние: выполнена локализация, полное оформление заблокировано сервисом.**
Файл JSON хранит желаемый, а не действующий шаблон. Брендированное оформление
пока не применено. Для произвольного оформления нужен выбор дальнейшего пути:
поддержка Firebase для разблокировки шаблона либо отдельный согласованный
почтовый отправитель. Проверка публичного имени — отдельный потенциальный путь
исправления `%APP_NAME%` без SMTP, но её результат пока не подтверждён.
Домен, DNS, SMTP, новый платный сервис и глобальное отображаемое
название проекта без отдельного согласования не менялись.

### Продолжение: собственного домена пока нет

Пользователь сообщил, что своего домена и почты пока нет. Новые сервисы не
подключались. Проверен бесплатный потенциальный путь через Public-facing name
/ OAuth brand name: это не внутреннее имя проекта. Firebase и Google Cloud
показывают внутреннее имя `tren`; переименование этого поля не считается
доказанным исправлением подстановки в письме и не выполнялось.

Чтение OAuth brand через IAP API вернуло HTTP 403. Первая попытка открыть
настройки Firebase в браузере была остановлена автоматической проверкой при
переходе на `accounts.google.com`. Обход ограничения не выполнялся.

Пользователь затем явно разрешил доступ к Google-сессии и только точечную
смену публичного имени проекта `tren-85720` на `Zmena`. Повторное открытие
Console дошло до выбора Google-аккаунта: аккаунт отмечен «Вы вышли из аккаунта».
Вкладка передана пользователю для самостоятельного входа. Публичное имя и
остальные настройки не изменены; продолжение ожидает входа пользователя.

Актуальное описание источника `%APP_NAME%`:
[Firebase Auth FAQ](https://firebase.google.com/docs/auth/faq-and-troubleshooting).
При наличии OAuth brand используется его имя; для веба без него применяется
fallback Hosting site name. Документация описывает email verification,
поэтому фактический результат для восстановления пароля потребует отдельной
проверки.
