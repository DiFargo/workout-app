# Исправления аудита — этап 1

Основание: [аудит 3.0.799](GEMINI_APP_AUDIT_3.0.799_2026-09-18.md), A01–A04.

18 сентября 2026. Подготовлена локальная версия **3.0.800**. В production по-прежнему **3.0.799**; публикация не выполнялась.

Обновление 19 сентября: по последующему запросу пользователя эти изменения опубликованы вместе с правкой календаря в [3.0.801](releases/3.0.801-calendar-and-audit.md). Ниже сохранён отчёт о первоначальной подготовке.

## Критерии приёмки

- [x] A01: приглашённый клиент создаёт только разрешённые поля профиля; Telegram, абонемент, alias и чужая роль/привязка не внедряются. Обычный вход по приглашению сохраняется; alias назначает существующий серверный API.
- [x] A02: сообщения «боль», «сильная боль.» и «в колене острая боль!» требуют проверки тренером в обоих режимах и не запускают ИИ или локальный fallback.
- [x] A03: завершение синхронизации питания старой сессии не меняет состояние/кэш нового аккаунта. Повторный вход в тот же UID, отложенный React setter и параллельные очереди также проверяются.
- [x] A04: после первого выполненного подхода замена упражнения недоступна с явным объяснением; исходные результаты не удаляются и не переходят другому движению. До начала упражнения обе разновидности замены работают.
- [x] Проверены профильные unit/Rules/UI-тесты, сборка, синтаксис и защищённые маршруты в релевантных smoke-сценариях. Ограничения общего набора приведены ниже, полного зелёного release-gate нет.

Правило A04 выбрано как минимальное безопасное исправление: разделение одного упражнения на историю выполненных и новый блок оставшихся подходов требует отдельного продуктового этапа. Кнопка закрытия и возврат к текущему упражнению сохраняются. Для ясности ограничения и восстановления контекста использован `ui-ux-pro-max`.

Публикация не входит в текущий запрос. Остальные A05–A18 и R01–R07 остаются в очереди аудита, не считаются исправленными этим этапом.

## Границы и следующий выпуск

- Это не клиническая проверка и не полная защита через ключевые слова: исправлена конкретная ошибка границ слова, без изменения политики обязательной проверки тренером.
- A04 намеренно не переносит оставшиеся подходы на новое движение. Ручная отмена отметок выполнения остаётся существующим явным действием пользователя.
- Для A03 проверяются UID и объект сессии после запроса и внутри React updater; занятость синхронизации разделена между UID/сессиями. Подтверждённая сервером запись старого пользователя может безопасно снять только его собственную версию очереди.
- Физические iPhone/Safari, live-регистрация и аутентифицированные production-записи не выполнялись. Новое поведение проверено локально и в Emulator, production smoke проверяет только неизменённую опубликованную базу.
- После разрешения на выпуск нужны Hosting, `functions:aiBasicWorkoutPlan` и `firestore:rules` для проекта `tren-85720`. Актуальный клиент больше не посылает `loginLower` при создании профиля; старую открытую версию следует обновить перед принятием приглашения. Изменять данные существующих профилей не требуется.
- Перед публикацией отдельно разобрать оставшийся release-gate (A15); этот отчёт не объявляет весь репозиторий зелёным.
