# Выпуск 3.0.933

Дата: 8 ноября 2026 года. Область: повторное чтение календаря после переноса оставшихся занятий. Публикация только Hosting `tren-85720`.

## Подтверждённая причина

Read-only проверка указанного клиента обнаружила уже сохранённые даты №6–8: 11, 14 и 18 ноября. Запись не откатывалась. Старые плановые даты выполненных №3 и №5 совпадали с новыми датами оставшихся занятий. Нормализатор резервировал дату лишь за первым ID и автоматически передвигал последующие занятия, в том числе при повторном вызове нормализации.

## Изменения

- Явные даты с `dateOrderPolicy: workout_identity`, точным ID занятия и совпадающим назначением сохраняются независимо от совпадения со старой плановой датой другого занятия.
- Неявные и устаревшие расписания по-прежнему проходят существующее устранение случайных повторов. Маркеры другого назначения не получают приоритет.
- Список календарных дат остаётся уникальным; отдельные записи занятий сохраняют свои даты по ID. Фактическая история выполнения не меняется.
- Браузерный сценарий теперь использует настоящий нормализатор, идентификаторы назначения и историю: выбор 11/14/18 → сохранение → перезагрузка страницы → повторное открытие редактирования. Ранее тест сохранения не покрывал повторное чтение.
