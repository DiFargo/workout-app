## Подтверждённые дефекты

### R01 · P1 · Завершившаяся синхронизация питания смешивает состояние двух аккаунтов

**Условие:** офлайн-очередь аккаунта A начала отправляться; до завершения запроса пользователь вышел и вошёл в B. Ответ A выполняет `setNutrition` над текущим состоянием B, объединяет дни обоих пользователей и устанавливает `__uid: A`.

**Доказательство:** воспроизведено настоящим обработчиком с подменой только Firebase/storage. После ответа `auth.currentUser.uid = B`, состояние помечено A и содержит записи обоих аккаунтов.

**Последствие:** данные предыдущего пользователя могут появиться в интерфейсе следующего на общем устройстве. Проверки `__uid` в autosave предотвращают обычную автоматическую запись такого состояния в B, поэтому запись чужих данных в облако B здесь не заявляется. Но интерфейс и дальнейшая синхронизация остаются некорректными.

**Источник:** [offlineReplayHandlers.js:71](C:/Users/workk/workout-app/src/features/client/offline/offlineReplayHandlers.js:71), [workoutPersistenceHandlers.js:38](C:/Users/workk/workout-app/src/features/client/workouts/workoutPersistenceHandlers.js:38). В обработчик не передаётся проверка актуальности сессии. Похожий незащищённый поздний ответ есть в [appBootstrapHelpers.js:379](C:/Users/workk/workout-app/src/app/appBootstrapHelpers.js:379) при гидратации Telegram; этот дополнительный путь отдельно не воспроизводился.

**Исправление:** токен поколения сессии/UID-guard после каждого await и внутри функционального setter; пользовательские in-flight-флаги вместо одного общего. Проверка: A → задержка → B → ответ A не меняет ни UI, ни кэш B.

### R02 · P2 · Сохранение настроек тренером может выключить все напоминания клиента

Клиентская версия разделяет общий выключатель Telegram, тренировки, фото и замеры. Тренерский редактор сводит общий выключатель и тренировки в одно `enabled`.

**Сценарий:** клиент оставляет Telegram и фото включёнными, выключает только тренировки. Тренер меняет период фото. Его сохранение записывает `telegram.notificationsEnabled: false` и `telegramNotificationsEnabled: false`, хотя фото остаются отмеченными.

**Доказательство:** настоящий обработчик сохранения с фиктивным `setDoc` сформировал именно такой patch.

**Источник:** [TrainerWorkspace.jsx:4240](C:/Users/workk/workout-app/src/components/trainer/TrainerWorkspace.jsx:4240), [trainerClientCalendarHandlers.js:454](C:/Users/workk/workout-app/src/features/trainer/trainerClientCalendarHandlers.js:454).

**Исправление:** один контракт настроек для обоих интерфейсов; изменения категории не должны менять master opt-out. Проверка: фото/замеры работают при отключённых тренировках до и после редактирования тренером.

### R03 · P2 · Ошибка одного напоминания скрывается и блокирует другие категории

Планировщик сначала ожидает все тренировочные отправки пользователя, затем переходит к фото/замерам. При отклонении первой операции до прогресс-напоминаний он не доходит. В конце `Promise.allSettled(jobs)` не анализируется: вызов планировщика формально завершается успешно.

**Доказательство:** извлечённый callback планировщика, фиктивная ошибка Telegram: `progressChecks = 0`, callback завершился без ошибки. Реальные сообщения не отправлялись.

**Источник:** [functions/index.js:1871](C:/Users/workk/workout-app/functions/index.js:1871), [functions/index.js:1906](C:/Users/workk/workout-app/functions/index.js:1906).

**Исправление:** изоляция задач по категории, обработка каждого rejected-результата, структурированные логи/счётчики доставки и ограниченные повторные попытки. Дополнительно стоит проверить идемпотентность границы «Telegram отправил, Firestore не записал результат» — текущий код сохраняет маркер после отправки, но дубли в этом ревью не воспроизводились.

### R04 · P2 · Приостановка аккаунта не исключает его из планировщика Telegram

Административное `suspend` выставляет `active: false`, `accessDisabled: true`, `membershipStatus: suspended`, но сохраняет Telegram-подключение. Планировщик выбирает `telegramConnected == true`, а `isTelegramRemindersEnabled` проверяет только два флага уведомлений. В отправителях дополнительной проверки активного членства нет.

**Доказательство:** фактический predicate возвращает `true` для suspended-клиента; цепочка выбора и отправки проверена в исходниках. Отправка заблокированному реальному пользователю не выполнялась.

**Источник:** [telegramNotificationPreferences.js:3](C:/Users/workk/workout-app/functions/telegramNotificationPreferences.js:3), [functions/index.js:1859](C:/Users/workk/workout-app/functions/index.js:1859), [functions/index.js:4280](C:/Users/workk/workout-app/functions/index.js:4280).

**Последствие:** отключённый аккаунт продолжает получать сообщения, но уже не может зайти в приложение, чтобы изменить настройки.

**Исправление:** явное правило жизненного цикла уведомлений и проверка `isActiveMemberData` перед автоматической отправкой. Не обязательно удалять Telegram-связь: после восстановления аккаунта её можно сохранить.

`users/{uid}/nutrition/state` содержит целиком `days`; каждая правка читает и переписывает этот документ в транзакции. Разбиения на дни/месяцы и границы архивирования в этом пути нет.

**Риск, не наблюдавшийся инцидент:** стоимость передачи, конфликтность и время сохранения растут с историей. У Firestore есть предел **1 MiB на документ** — после достижения предела дальнейшие сохранения не пройдут. Размер реальных пользовательских документов в этом ревью не измерялся. [Официальные ограничения Firebase](https://firebase.google.com/docs/firestore/quotas#collections_documents_and_fields).

**Исправление:** дневные документы, небольшой отдельный документ целей/настроек, ограниченная выборка истории; миграция с совместимым чтением и проверкой сохранности данных.

- В проверенных экранах питания/прогресса измеренные кнопки не оказались меньше 44×44. У нижней навигации есть `aria-current`, окна программы/поиска закрываются, фокус возвращается.
- Локальный экран упражнения с тремя подходами помещается при 402×874; разминка визуально помещается при 375×667. Ошибочную картинку упражнения в локальном harness нельзя считать ошибкой production-каталога: это фикстура.
