# Сохранение замены видео в библиотеке — 3.0.765

## Причина

`uploadTrainerLibraryExerciseVideo` сразу сохранял новое видео в шаблон, хотя редактор обещает применять изменения только кнопкой «Сохранить». Затем редактор отправлял старый снимок упражнения. `patchLibraryExercise` ищет точное совпадение ID и варианта видео, поэтому уже изменённая ссылка вызывала конфликт. Его конкретное сообщение скрывалось за общим текстом ошибки.

Регрессионные тесты до исправления подтвердили запись в шаблон уже при загрузке (1 запись вместо 0).

## Критерии готовности

- [x] Загрузка отправляет файл в Storage и возвращает URL, но не изменяет упражнение в Firestore.
- [x] Предпросмотр обновляется в черновике; только «Сохранить» выполняет транзакцию изменения библиотеки.
- [x] Закрытие без сохранения оставляет старую ссылку в библиотеке.
- [x] Во время загрузки нельзя одновременно сохранить, удалить или закрыть редактор; виден статус загрузки.
- [x] Ошибка загрузки сохраняет черновик и разрешает повторную попытку. Реальный конфликт другого окна сохраняет своё понятное сообщение.
- [x] Количество подходов, повторы и веса в разных днях шаблона не меняются при замене видео. Назначенные клиентские планы и история не записываются.
- [x] Убрана прежняя ветка, которая из библиотечного загрузчика немедленно записывала видео в клиентский план. Такой источник, как и при сохранении библиотеки, требует отдельного редактора программы.
- [x] Права доступа, Storage/Firestore rules и проверка конфликтов не ослаблены.
