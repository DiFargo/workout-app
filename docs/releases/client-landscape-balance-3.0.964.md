## Проверки

В каждом из Chromium и мобильного WebKit пройдено:

- 50 сочетаний: пять вкладок, обе темы, размеры 874×300, 740×280, 568×250, 402×874 и 375×812. Проверены фактические размеры и совпадающие границы парных секций, полная ширина главной карточки, сохранение портретных шапок, угловые кнопки и достижимость последних действий над меню.
- 32 дополнительных сценария при 568×250 и 874×300: отсутствие программы, завершение тренировки сегодня, длинные и нечётные наборы задач, ошибка загрузки, разные состояния тренировок/базовой программы, первый/отсутствующий вес, реальный график за всё время, текущий и исторический день питания. Активная вкладка проверяется явно. Необработанных ошибок JavaScript не обнаружено.
- 16 проверок облачка: `cloud`, `local`, `saving`, `error` × две темы × два горизонтальных размера. Использован реальный `NutritionSyncRecovery` из существующей IO-изолированной фикстуры, через React portal в настоящую карточку питания. Auth, Firestore и API подменены; внешний IO заблокирован/замокан. Проверено положение индикатора, границы popup над меню, доступность повтора после прокрутки и закрытие панели.

Дополнительно в каждом движке проверены пять вкладок при базовом размере текста 20 px, reduced motion и синтетических Telegram-отступах top 12 / right 24 / bottom 21 px. Переполнения и перекрытия угловых действий нет.

Всего 206 локальных UI-проверок. На части загрузок DEV-harness Google возвращает ожидаемый HTTP 400 для фиктивного e2e Firebase API key; это не Production-запрос и не успешная проверка реальной авторизации. Ошибки `synthetic network failure` в IO-фикстуре намеренно создаются для состояния `error`.

Сборка Node 22: начальный вход 72,04 / 100 КиБ gzip, обязательный boot 525,59 / 640 КиБ, Firebase 159,69 / 170 КиБ. E2E-harness отсутствует в Production-артефакте. Существующее предупреждение Vite о крупных chunks не является ошибкой сборки.

Навык `ui-ux-pro-max` использован для группировки по приоритету, естественной высоты/переноса текста, сохранения зон нажатия и безопасных отступов; раскладка проверена на реальном DOM через Playwright. Компоненты React не переписывались и нового состояния не добавлялось.

Локальные сценарии и снимки находятся в `output/playwright/` проверочного worktree `.tmp/client-landscape-balance-3.0.964`. Проверка на физическом телефоне внутри Telegram не выполнялась.
