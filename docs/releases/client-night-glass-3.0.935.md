# Исправление клиентской тёмной темы — 3.0.935

## Причина

В 3.0.934 модуль `ClientAppearance.module.css` подключался только побочным импортом. В режиме разработки Vite загружал его, но оптимизация Production удаляла модуль как неиспользуемый. Поэтому проверка темы на локальном стенде не подтверждала её наличие в опубликованном приложении.

## Изменения

- Корневой класс оформления теперь явно используется клиентским обработчиком темы. CSS сохраняется в готовом артефакте и снимается при выходе из клиентского интерфейса.
- Уточнён приоритет клиентской палитры относительно старого светлого контракта. Выбор в кабинете показывает текущую тему и сохраняется на устройстве.
- Размеры шрифтов, отступы и группировка пяти главных страниц приближены к точным параметрам предоставленного HTML. Реальные значения и действия не подменяются демонстрационными.
- Добавлен контроль готовых CSS-файлов перед подготовкой релиза: сборка без тёмной палитры не проходит.

## Проверки

- 19 профильных тестов прошли; ESLint изменённых JS/JSX и скриптов прошёл.
- Пять клиентских страниц проверены в светлой и тёмной темах на стенде с вымышленными данными. Нет ошибок выполнения и горизонтального переполнения при 402 × 874.
- Переключение темы и её сохранение после перезагрузки проверены через пользовательские кнопки кабинета.
- CSS Production проверен отдельно в чистой странице браузера: тёмный фон `#08080b`, текст `#eff5f8`, `color-scheme: dark`. Это не проверка только dev-стилей.

Это исправление темы и уточнение интерфейса, не заявление о пиксельной идентичности всех состояний приложения с демонстрационным макетом. Firebase, роли, история, правила доступа и серверные функции не изменяются.
