## Причины

`data-app-theme="warm-light"` остаётся частью iOS-оболочки при обоих значениях `data-client-appearance`. Поздние правила в `WorkoutDialogs.module.css` ошибочно принимали этот признак за светлую тему и возвращали белые подложки. Мобильный `-webkit-text-fill-color` отдельно перекрывал новый цвет текста кнопок. Исправлены исходные локальные правила, без глобального перекрашивания тренерских и административных экранов.

Главная прежде всегда получала строку «Открыть тренировку». Теперь используется состояние реального назначения: «Начать раньше», «Начать тренировку», «Продолжить тренировку» или «Посмотреть результаты». Существующий переход и подтверждение раннего старта не обходятся; история и черновики не изменяются.

Окно подтверждения административного действия имело слой ниже тренерского модального окна. Оно перехватывало фокус, оставаясь за ним. Дополнительно прежний `setDoc` мог ждать восстановление сети без завершения UI-операции.

Для выдачи и отзыва доступа используется ограниченный по времени REST-запрос под теми же Firestore Rules и подтверждением администратора. Изменяются только `basicWorkoutAccess` и `updatedAt`, с проверкой серверного `updateTime`. При потере ответа успех признаётся только после отдельного чтения с точным маркером этой операции; смена сеанса отменяет ожидание. SDK-очередь отложенных записей здесь не используется.
