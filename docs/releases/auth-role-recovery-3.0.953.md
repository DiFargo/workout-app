# GymDuck — восстановление проверки роли 3.0.953

## Исправление

- Клиенты и тренеры не ждут принудительного обновления административных claims. Для администратора сохранены принудительное обновление токена, сверка серверной роли и версии полномочий, а затем отдельная защита ключом.
- Проверка профиля имеет предел 15 секунд. Только ошибки соединения получают до трёх попыток с ограниченной задержкой; отказ доступа, недействительный профиль или сессия не маскируются под сетевой сбой.
- Повтор выполняется на месте: без перезагрузки, смены auth-сессии и потери кнопки выхода. После исчерпания попыток пользователь может явно повторить проверку.
- Возврат приложения на передний план и восстановление сети не создают параллельные повторные запросы. Поздние ответы после тайм-аута, выхода, смены аккаунта или объекта Firebase User игнорируются.
- Неподтверждённая роль не открывает клиентские данные. SDK-кэш не становится новым основанием доступа при недоступном маршруте VPN; существующий явно офлайн-сценарий не расширяется.
- Экран различает проблему соединения, сессии, профиля и прав, сохраняет светлую/тёмную тему и доступные кнопки.

## Границы

Точечная согласованная проверка реального аккаунта подтвердила активную клиентскую роль, назначение тренера и согласованную привязку Telegram. Аккаунт не изменялся. Просроченное приглашение не требуется для обычного входа уже привязанного аккаунта.

Конкретный маршрут VPN клиента не воспроизводился: исправляется выявленный механизм зависания и ошибочного сообщения, а не заявляется гарантированная доступность Firebase через любой VPN.

## Проверка и выпуск

Критерии: вход трёх ролей; отсутствие доступа при неверных полномочиях; ограниченное восстановление после сетевого сбоя; изоляция сессий; корректные офлайн-границы; читаемый экран повторной проверки на телефоне в обеих темах.

Публикация — только Firebase Hosting `tren-85720`, из отдельного архива целевого коммита. Functions, Rules, технические домены и реальные пользовательские записи не меняются. Временные аккаунты для согласованной живой проверки подлежат полной очистке.

Проверки выбираются пропорционально точечному изменению согласно `AGENTS.md`: focused auth/role/session/security/invite tests, ESLint изменённых файлов, production build, artifact/bundle checks и живой вход тестовых ролей. Полный `verify:full` для этого Hosting-only исправления не запускается; миграций Rules/Functions и зависимостей нет.

Ранее одобренное превышение Firebase core 189,04 KiB gzip при лимите 170 KiB допустимо только при совпадении файла с текущей Production по SHA-256; лимит не изменяется.
