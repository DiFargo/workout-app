## Проверки

В каждом из Chromium и мобильного WebKit пройдено 116 проверок:

- 60 сочетаний: пять вкладок × две темы × размеры 874×300, 740×280, 667×300, 568×250, 402×874 и 375×812. Проверены фактическая компактность четырёх групп, отсутствие пустого растяжения, header reserve, полная ширина строк и доступность последних действий над dock.
- 32 дополнительных состояния: нет программы, выполненная сегодня тренировка, длинные/нечётные задачи, ошибка загрузки, базовая и завершённая программы, пустой/первый вес, реальный график за всё время, текущий/исторический день питания.
- 5 вкладок с базовым текстом 20 px, reduced motion и синтетическими Telegram-отступами top 12 / right 24 / bottom 21 px.
- 16 состояний облачка (`cloud`, `local`, `saving`, `error` × две темы × два размера) реальным `NutritionSyncRecovery` с подменёнными Auth/Firestore/API и заблокированным внешним IO. Проверены привязка к общей карточке, границы popup и доступность повтора.
- 3 открытия/закрытия голосового окна после перехода между портретом и двумя горизонтальными размерами. Пробный клик дожидается завершения анимации. Фото AI открыл штатный file chooser; файлы не выбирались и не отправлялись.

Всего 232 UI-проверки, необработанных ошибок JavaScript не обнаружено. DEV использует фиктивные e2e Firebase-значения; возможный HTTP 400 на getProjectConfig и намеренная `synthetic network failure` фикстуры не являются Production-проверкой авторизации. Сценарии/снимки находятся в `output/playwright/` этого worktree. Физический Telegram не проверялся, реальные аккаунты и клиентские данные не читались.

Навыки `ui-ux-pro-max` и `vercel-react-best-practices` помогли сохранить естественную высоту, перенос текста и существующие обработчики без нового состояния или зависимостей. Playwright использован для проверки фактического DOM в двух движках.
