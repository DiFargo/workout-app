# 3.0.805 — повторные упражнения в библиотеке тренера

## Причина

После появления общих карточек `buildTrainerExerciseLibraryItems` возвращал карточки вместе с неприкреплёнными копиями из шаблонов, без прежнего приоритета видео. Следующее объединение в рабочем пространстве группировало карточки по ID, а старые записи — по названию. Одинаковое упражнение с видео и его пустая копия попадали в разные группы.

## Исправление

Один алгоритм формирования списка применяется ко всей библиотеке, включая конструкторы программ. В пределах одного владельца учитываются нормализованное название и техника; различные видео сохраняются. Пустые повторы уступают версии с видео. Среди точных повторов предпочтительна общая карточка; среди одинаковых карточек — последняя изменённая. ID, revision и источник редактирования не смешиваются.

Сохранённые старые идентификаторы карточки также учитываются для пустых копий. Поэтому переименование, замена видео или изменение техники не возвращает старую пустую запись. Маркер удаления учитывается до фильтрации: удалённое упражнение не появляется снова в виде старой копии.

Это исправление представления библиотеки, не удаление документов. Нагрузки, клиентские программы, история, Firebase Functions и правила доступа не изменялись. Различающиеся техники, положения тела, видео и владельцы остаются отдельными.

## Критерии готовности

- [x] Дубли с видео/без видео убраны по общей логике, не по списку из двух примеров.
- [x] «Сидя» и «стоя» не объединяются; другие видео, техники и владельцы сохранены.
- [x] Повторное применение алгоритма не меняет результат.
- [x] После изменения карточки, удаления и восстановления старые пустые копии не возвращаются.
- [x] Редактирование направлено на исходную карточку с её revision.
- [x] Исходные шаблоны и нагрузки не изменяются.
- [x] 41 целевой unit-тест, 8 Playwright-сценариев на 320 px и 1366 px.
- [x] ESLint изменённой логики и тестов, production build, bundle budget, git diff --check.
- [x] Публикация Hosting и read-only production smoke.

Первоначальный тест воспроизвёл проблему: вместо четырёх карточек вернулось 12 строк. После исправления он и проверки разных вариантов проходят. Браузерная проверка проходит через реальный обработчик карточек на изолированной тестовой БД и подтверждает, что записывается только выбранная карточка, а шаблон не меняется.
