## Актуальные проверки

- Устаревшие точки входа и селекторы заменены текущими действиями интерфейса: сообщения, задания, календарь, история, назначения, редакторы и desktop/mobile-навигация. Проверки действий, сохранения, геометрии и ошибок сохранены.
- Fixture успешного AI-плана содержит обязательный целевой вес; состояния графика реально различают две записи, одну запись и пустую историю. Завершённый подход отменяется перед проверкой замены упражнения; запрет замены выполненного подхода также проверяется. Таймер проверяется управляемыми часами, включая скачок времени и защиту от повторного завершения: эти проверки не заменены ожиданием обычного тика.
- Видео-fixture отдаёт настоящий ролик локально с поддержкой Range/перемотки, без незавершённого сетевого запроса при закрытии страницы.
- Rules runner явно использует локальный `demo-workout-rules` и проверяет Firestore вместе со Storage; cross-service тест использует тот же project ID.
- `verify:core` выполняет проверки без полного E2E-набора; `verify:full` добавляет весь Playwright suite. Один тест настоящего React DOM требует Chromium уже в `npm test` и `verify:core`: установка добавлена перед unit tests в CI и описана для чистого локального окружения. Короткий `verify` проверяет сборку/бюджет и не заменяет полный gate.
- CI и полный gate проверяют зависимости разработки клиента вместе с runtime и обе Functions codebase: `functions` и `functions-telegram-auth`. Syntax/audit берут перечень из `firebase.json`; CI учитывает оба lockfile и выполняет обе чистые установки. Firebase не откатывался; совместимые версии и точечные overrides устранили advisories. Чистый `npm ci` и `npm ls --all` выполнены для всех трёх деревьев.
- Общие UI-fixtures изолируют только транспорт внешнего Telegram SDK, включая десять страниц в явно создаваемых контекстах. Посвящённый SDK spec использует исходный Playwright и управляемые задержанный/неудачный ответы. Проверки текущего login, приглашения, поздней инициализации SDK и ошибок приложения сохранены.

## Границы

Исторические AI-планы не мигрируются массово: исправленная арифметика применяется при пересчёте. PDF browser proof проверяет документ, изоляцию и вызов печати; системный диалог сохранения проверяется пользователем. Windows WebKit не декодирует используемый H.264 fixture: реальное воспроизведение проверяется Chromium, WebKit покрывает layout и недоступное видео; Safari playback остаётся платформенной проверкой.

В ESLint остаются прежние 38 предупреждений; ошибки не допускаются. Бюджет entry измеряет стартовую оболочку и React, а не весь загружаемый далее App. Прежнее предупреждение о большом App chunk не подавлено и не считается устранённым рефакторингом.

Для применения серверных исправлений требуется согласованный выпуск Firestore/Storage rules и обеих Functions codebase вместе с клиентом.
