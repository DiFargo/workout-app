# 3.0.779 — быстрый поиск продуктов

Текстовый поиск снова выдаёт продукты при вводе. В браузере используется каталог из 10 000 карточек: 7 416 Open Food Facts и 2 584 объединённых карточки нового списка Gemini. Парсинг и индекс префиксов выполняет Web Worker; CacheStorage сохраняет каталог между открытиями. Штрихкод ищется точным совпадением, названия — с вариантами брендов, одной опечаткой и исправлением раскладки.

Gemini остаётся отдельной кнопкой. Результаты по прошлому запросу не перезаписывают текущий. Записи без единицы КБЖУ требуют указать исходную массу/объём перед расчётом порции. Полный список и исходные записи сохранены в `output/belarus-products-10000/`; 437 карточек имеют отметку Беларуси в источнике, доступность остальных в стране не подтверждена.

## Проверено

- 44 профильные проверки: каталог, адаптер, КБЖУ, порции, синхронизация, совместимость, Gemini и существующие границы доступа.
- Мобильные сценарии: автоматический поиск, раскладка, штрихкод, кеш после перезагрузки, отсутствие сетевых запросов при локальном поиске, ручной Gemini, «Моя база», уточнение единицы.
- Выбор приёма пищи, изменение порции, пересчёт КБЖУ и добавление в дневник проверены изолированным сценарием `food-screens-compact`.
- `npm run verify` с профилем release: сборка production, бюджет первого входа, `git diff --check`.
- ESLint изменённых компонентов поиска и адаптера: без ошибок.

Публикация ограничена Firebase Hosting; Functions, Auth, Firestore и Storage не разворачиваются. Замеры самостоятельной страницы на этом компьютере: старт около 0,6 с, поиск и отрисовка 4–14 мс при эмуляции замедления CPU; это не замер на физическом телефоне.
