## Проверки вне автоматизации

Приёмка на физических iPhone/Android и доставка реальных уведомлений требуют участия пользователя; результаты эмуляции не считаются такой приёмкой.

## Ход работы

- A01–A04: закрыты клиентские записи в служебные коллекции; alias и email меняются сервером, email требует свежего входа; отзыв назначения учитывается серверными обработчиками.
- A05–A08: pending-очереди не сокращаются при quota; replay подтверждает только отправленную версию; загрузка питания учитывает текущий ввод; записи дня и удаления сливаются по ID/версиям; удаление из своей базы сохраняет прошлый дневник.
- A09–A10: голос передаёт commit/cancel через NutritionOrbit; обычная правка библиотеки использует транзакцию с проверкой свежей версии и владельца.
- B01–B05: таймер продолжает отсчёт после изменения времени; замеры не откатывают профиль; завершение и прогрессия атомарны и идемпотентны; tombstone исключает возврат удалённой пользователем истории; устаревшая загрузка режима игнорируется.
- B06–B11: поздний ответ отменённого фото игнорируется; ингредиент требует положительный вес; открывается следующий незавершённый день; календарь использует местную дату; анкета сохраняет профиль и цели атомарно; кнопка честно названа «Сохранить программу».
- B12–B15: фактические назначения считаются тем же selector, что в редакторе; кабинет/аналитика используют общие статусы; есть восстановление запуска; CSV нейтрализует формулы; повтор фото использует устойчивую сессию.
- B16–B19 и V01–V04: исправлены геометрия шапки и строк еды; разрешены масштабирование/копирование/поворот; подписи metric inputs доступны; нет выдуманного процента восстановления; единственная история не называется отсутствующей; review анкеты редактируется по одному полю; тестовый клиент имеет отдельную отметку/фильтр и не входит в KPI; продолжение черновика основное, readiness собран в одну sheet.
- Никакие реальные записи клиентов, программ, упражнений, тренировок или истории этой работой не удалялись и не маркировались автоматически.
- Проверки поведения используют реальные импорты с подменой только внешних I/O; Firestore-транзакции выполняются в Emulator. Новые сценарии покрывают partial upload/retry, cancellation, quota, concurrent replay, identity collision, basic calendar и запрещённых actors.
- Профили scripts/verify.mjs: docs/ui/domain/persistence/auth/release/full. Профильные domain/persistence/auth требуют явного списка --tests; браузерный набор задаётся --browser; dependency audit запускается при --dependencies или full. Версии экранов не повторяются во втором browser project без причины.
- Опубликован релиз 3.0.756: Hosting, Firestore Rules и девять затронутых Functions. Проверены опубликованные ресурсы и открытие приложения. Подробности: [релиз 3.0.756](RELEASE_3.0.756_2026-09-10.md).

## Обоснование изменений интерфейса

| До | После | Зачем |
|---|---|---|
| Шапка шире фиксированного контейнера; узкая колонка названия еды | Размер по фактической ширине шапки; гибкая колонка описания | Действия и названия помещаются на телефоне |
| Нельзя масштабировать, копировать, менять ориентацию; textbox без имени | Стандартные возможности браузера и доступные подписи | Доступность и удобный ввод |
| Анкета требует проходить последующие шаги повторно | Выбор поля в review → изменение → «Готово» | Быстрое исправление ответа |
| Равнозначные действия сброса/продолжения; отдельный плавающий footer | Основное продолжение с фокусом; единая sheet | Меньше случайных сбросов и понятная композиция |
| Нет истории при одном выполнении; произвольные проценты готовности | Отдельно наличие истории и возможность сравнения; честная свежесть данных | Правильное понимание своих результатов |

## Использование выборочных проверок

Пример: `npm run verify -- --profile=persistence --tests=tests/offline-runtime-regression.test.mjs,tests/nutrition-sync-regression.test.mjs --browser=tests/e2e/audit-runtime-regressions.spec.js`.
Обычная публикация: build + bundle + проверки по diff и smoke после deploy. Полный прогон оставлен явной командой `npm run verify:full`.


## Итоговая приёмка

- Синхронизация не обновляет время изменения записи только из-за повторной отправки; актуальные независимые изменения проверены транзакциями Emulator.
- 749 существующих и новых Node-проверок прошли. Полный недорогой набор использован для этого релиза из-за изменений общих сохранений; обычные следующие изменения используют профиль по риску.
- 37 проверок Firestore Emulator прошли, включая запреты посторонним ролям, атомарное завершение/повтор, замеры и редактирование библиотеки.
- 28 различных целевых сценариев Chromium проверены несколькими выборочными запусками: тренерская часть и библиотека, голос, таймер/анкета/геометрия/восстановление запуска, переходы из заданий тренера. Повторные запуски исправляли ожидание холодной загрузки и изменения выбранной карточки после переключения фильтра; они не считаются дополнительным покрытием.
- Production build, проверка размера bundle, Functions syntax и diff прошли. ESLint изменённых файлов: 0 ошибок, 25 предупреждений React/hooks.
- Опубликованные HTML/JS/CSS проверены на соответствие локальной сборке; 10 защищённых API вернули 401 без авторизации. В рабочей вкладке новая версия открыла экран тренировок существующего тестового клиента.
- V01: явно подписаны последнее выполнение и дата предыдущего выполнения, от которого рассчитано сравнение.
- V02: реализован прямой переход к отдельному полю из подтверждения анкеты с возвратом к подтверждению. Предложение объединить вопросы в новые группы остаётся вариантом для совместной UX-пробы; текущие поля и расчёты сохранены.
- V03: тренер может помечать клиентов и программы как тестовые; есть отдельные фильтры. Отметка программы сохраняется с программой. Автоматическая классификация реальных данных не выполнялась.

Ограничения приёмки: физические iPhone/Android, VoiceOver, аппаратные камера/микрофон, Google/Telegram round-trip и доставка реальных уведомлений, длительная работа с плохой сетью и восстановление после завершения процесса приложения. Эмулятор и Chromium не заменяют эти проверки. Приватные ссылки на фото, масштабирование инфраструктуры и эксплуатационное восстановление требуют отдельной проверки, как указано в исходном аудите.
