# Тренерская часть: анализ и расширенный макет

[Открыть интерактивный макет](trainer-workspace-prototype.html) · [Первый вариант](trainer-calm-blue-mockup.html)

## Основа и границы

Макет опирается на текущие исходники, а не на предположение о том, какие функции нужны тренеру. Рабочее приложение, доступы, Firebase и версия не изменены. Это предложение структуры и взаимодействий, а не перенос приложения на демонстрационные данные.

Прочитаны основные разделы `TrainerWorkspace.jsx`, текущий `TrainerProgramConstructor.jsx`, оболочка `TrainerProgramManagerView.jsx`, обзор программ, редактор дня, первичная настройка и сценарии существующих e2e-тестов. Тесты использованы как карта защищаемых сценариев; runtime-тесты в этой задаче не запускались.

Визуальный ориентир — текущая клиентская часть и `client-five-main-screens-signature.html`: нейтральный iOS-фон, белые компактные группы, сдержанный синий акцент. `ui-ux-pro-max` использован для проверки структуры, полей и доступности; `emil-design-eng` — для обратной связи, раскрытия деталей и скорости взаимодействия. Рекомендации навыков не подменяют продуктовые требования.

## Что обнаружено

Тренерская часть уже содержит четыре главных раздела: Главная, Клиенты, Программы, Кабинет. В первом макете кабинет был спрятан за «Ещё», а тренировки конкретного клиента смешивались с библиотекой программ. Кроме того, он не показывал абонементы, сообщения и их обработку, задания, первичную настройку, историю назначений и конструктор.

Карточка клиента в исходниках гораздо шире сводки показателей. В ней есть анкета, статус абонемента, календарь, отдельные вкладки тренировок и питания, фото и 12 замеров, сообщения, задания, напоминания, архив и экспорт. До завершения анкеты предусмотрено состояние ожидания; оно должно сохраниться при реализации.

Конструктор поддерживает месяцы, микроциклы, недели, дни и упражнения; копирование и перестановку; видео и альтернативы; параметры подходов; суперсеты, трисеты, круги, интервалы и свободные задания. Упрощение визуального слоя не должно сокращать эту модель.

## Решения по интерфейсу

| Before | After | Why |
| --- | --- | --- |
| «Ещё» вместо существующего кабинета | Явная вкладка «Кабинет» | Сохраняет знакомую навигацию и обозначает место настроек |
| Карточка клиента ведёт в общую библиотеку тренировок | Отдельная страница назначенной программы клиента | Видно, чьи данные и какой объект изменяются |
| Общий сигнал «проверить» | Причина, клиент и действие рядом | Тренер может сразу начать работу |
| Шесть иллюстративных экранов | 21 связанная страница и листы действий | Показывает глубину ежедневных сценариев |
| Все настройки потенциально на одном экране | Повторы и вес сразу; расширенные параметры раскрываются | Снижает перегрузку без потери точек входа |
| Перестановка могла бы зависеть от жеста | Кнопки выше/ниже и копирования | Работает мышью, касанием и клавиатурой |
| Неочевидное сохранение | Статус черновика и отдельное сохранение программы | Различает изменение упражнения и сохранение всей программы |
| Одинаковая окраска статусов | Текст статуса и умеренный смысловой цвет | Смысл доступен без различения цветов |
| Длинные переходы между часто используемыми страницами | Мгновенные переходы, короткая реакция на нажатие | Интерфейс не замедляет повторяемые действия |

## Карта сохранения функций

| Существующая возможность | Место в новом макете | Уровень демонстрации |
| --- | --- | --- |
| Главная и центр внимания | Главная → важное → клиент | Переходы, сигналы и следующий шаг |
| Поиск и фильтры клиентов | Клиенты | Поиск, активные, внимание, без программы, архив |
| Создание клиента | Клиенты → добавить | Поля и подтверждение; письмо не отправляется |
| Анкета клиента | Карточка → анкета | Сводка и точка входа; полный состав полей сохраняется в runtime |
| Первичная настройка | Карточка → настройка | Пять шагов и переходы к редакторам; демонстрационный чеклист |
| Назначенная программа | Карточка → тренировки | Отдельно от шаблона библиотеки |
| Абонемент | Карточка / календарь → абонемент | Лист срока, статуса и количества занятий |
| Календарь назначения | Тренировки → расписание | Выбор дат и сохранение в памяти макета |
| История назначений | Тренировки → история назначений | Активная/архивная программа и подтверждение восстановления |
| История тренировок | Тренировки → история | Пример выполненных подходов и переход к сообщению |
| Анализ упражнений | Тренировки → прогресс упражнений | Сравнение сессий, оставить/адаптировать нагрузку |
| Сообщения | Карточка → сообщения | Пример ответа и обработки без отправки |
| Задания | Карточка → задания | Добавление задания в памяти |
| Дневник питания | Карточка → питание | Даты, пустой день, приёмы пищи, состав |
| Планы и цели питания | Питание → цели | Редактирование калорий и БЖУ |
| AI-план питания | Питание → подготовить AI-план | Этапы: данные → черновик → проверка → сохранение |
| Фото и 12 замеров | Карточка → фото и замеры | График, полный список замеров, честное пустое состояние фото |
| Напоминания | Карточка / кабинет → настройки | Разделение индивидуальных и общих правил обозначено |
| Архивирование клиента | Карточка → действия | Архив/восстановление в памяти макета |
| CSV и PDF | Карточка → действия | Точки входа; экспорт не выполняется |
| Библиотека программ | Программы | Поиск, создание, копирование, предпросмотр |
| Импорт из файла и AI-разбор | Программы → создание | Последовательность проверки без чтения файлов и AI-запросов |
| Иерархия программы | Программы → конструктор | Один микроцикл, отдельные недели, дни и упражнения |
| Несколько месяцев/микроциклов | Конструктор → структура | Обязательное требование к переносу; создание не моделируется |
| Редактор тренировки | Конструктор → тренировка | Добавление, копирование, удаление дня; порядок упражнений |
| Редактор подходов | Тренировка → упражнение | Количество подходов, повторы, вес, отдых, заметка |
| Расширенные параметры | Упражнение → расширенные параметры | RPE/RIR, темп, тип, %1ПМ, время, дистанция, скорость, сторона, отказ, AMRAP |
| Видео и альтернативы | Упражнение | Поля и сохранение черновика; без загрузки/воспроизведения |
| Специальные блоки | Тренировка → добавить блок | Демонстрационный блок с типом и параметрами |
| Назначение и адаптация | Программы → назначение | Выбор клиента, даты, режима замены, затем календарь |
| Кабинет и профиль | Кабинет | Имя, показатели, рабочие разделы и аккаунт |
| Аналитика | Кабинет → аналитика | Пример сводки и переход к нужному клиенту |
| Уведомления | Кабинет → уведомления | Важные/все/фоновые события |
| Почта, пароль, Telegram | Кабинет → подключения | Состояния и точки входа без операций с аккаунтами |

## Что важно при переносе в приложение

1. Стили накладывать на существующие обработчики и CSS Modules. Не заменять их логикой макета.
2. Сохранить доступ только к закреплённым клиентам; роль администратора и её действия проверять отдельно.
3. Не смешивать шаблон, активное назначение, архив назначений и базовую программу клиента.
4. Не менять завершённые подходы при адаптации будущей нагрузки.
5. Сохранить все поля подходов на уровне каждого подхода. В макете часть расширенных полей показана на уровне упражнения для демонстрации компоновки.
6. Сохранить реальную модель специальных блоков, альтернатив и нескольких микроциклов. Макет показывает их место, но не воспроизводит всю доменную модель.
7. Сохранить черновики и защиту от случайной потери правок, реальные ошибки загрузки и сохранения, ожидание анкеты и отсутствие данных.
8. Отправка сообщений, настройки доставки и обработка сообщения — разные действия; не считать просмотр отправкой или ответом.

## Ограничения

Это прототип интерфейса, не полная копия приложения. Примеры истории, аналитики, фотографий и AI не являются результатами работы сервисов. Данные исчезают при перезагрузке; ограниченные демонстрационные редакторы не заменяют текущие доменные модели. Дизайн не является доказательством сохранности runtime-функций — их проверка потребуется при реализации.

Проверка прототипа: `node artifacts/check-trainer-prototype.mjs`. Выполнена визуальная проверка общего обзора, конструктора и мобильного редактора упражнения. Проверка относится к браузерному макету, не к production-потокам.
